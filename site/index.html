agent.kompo.se

Make music videos with your LLM, from the terminal. kli is the agent-first command-line client for kompo.ai: you bring audio and footage plus an LLM agent, kompo.ai analyzes your media (BPM, beat grid, MusicDNA), and your agent composes a beat-timed komposition that the platform renders into a finished video. No web UI in the loop — the whole flow runs in your own project directory, and the service is self-describing via KCP so your agent can discover every operation on its own.

Where things stand. kompo.ai accounts are invitation-only — request access by opening an issue. The @kompo/kli npm package is not published yet; today you clone the repo and run it with Bun (30 seconds, below). Without an account you can still explore everything that matters for evaluation: the knowledge manifest, the komposition format, the full CLI, and the public health and discovery endpoints.

What a komposition is

A komposition is a markdown document that describes a music video: BPM, beat timings, visual tracks, and which uploaded files to use. There is no timeline UI — you (or your agent) write this directly, and the platform renders it.

# My First Video

## Metadata
- BPM: 128

## Tracks

### Visuals
- [FILE_ID](source-video) "Opening clip"
  - Start: 0 beats
  - End: 16 beats

### Audio
- [FILE_ID](source-audio) "Track"
  - Start: 0 beats
  - End: 16 beats

Beats, not milliseconds — duration = beats × 60 / BPM. Full spec: komposition-format.md.

The six workflows

  1. 1
    Bootstrap & discovery The tools manifest describes every callable operation, its HTTP method, path, and input schema. kli init fetches the knowledge manifest and writes agent-readable project context.
  2. 2
    Authentication PKCE paste-back login via kli auth/url → kli auth/complete <callback-url>. No cloud credentials leave your machine.
  3. 3
    Upload Upload audio, video, and image files to your media library via presigned S3 URLs.
  4. 4
    Analyze & tag kilder Metadata extraction (BPM, beat grid, MusicDNA) creates tagged Kilder — reusable media source catalog entries with segment definitions.
  5. 5
    Compose a komposition Create a markdown document (komposition) describing your music video: BPM, beat timings, visual tracks, and which kilder to use. Compose via natural-language chat or the CRUD API directly.
  6. 6
    Build, poll & download Submit the komposition for rendering. Poll job status (PENDING → RUNNING → SUCCEEDED) and download the finished .mp4.

Get started

kli runs on Bun. Until the npm package ships, clone and run directly:

git clone https://github.com/StigLau/agent.kompo.se.git
cd agent.kompo.se && bun install
bun src/cli.ts help        # full command reference
bun src/cli.ts health      # is the API up? is KCP discovery intact?

With an account, the first session looks like this — run it from your music/video project directory and let your agent drive:

kli init                       # fetch discovery, write AGENTS.md for your agent
kli auth/url                   # prints a PKCE login URL — open it, log in
kli auth/complete "<callback-url>"   # paste the full address-bar URL back
kli upload-analyze track.mp3   # upload + queue BPM/beat-grid analysis
kli workstate/load-file my-video.kompo.md   # register your komposition
kli workstate/render-qc        # build, poll to completion, resolve stream URL

The full zero-to-first-video walkthrough — including what your agent should do at each step and how to verify the output — is in Getting started.

How your agent gets oriented — KCP

This site is the machine-readable documentation. The Knowledge Context Protocol manifest at /knowledge.yaml describes the kompo.ai domain as 16 knowledge units. Each unit declares an intent (the question it answers), triggers (phrases that should route to it), a dependency graph, and a path to its markdown body under /docs/kcp/. An agent orients itself in four fetches:

1. GET https://agent.kompo.se/knowledge.yaml         # the map: units, intents, triggers, dependencies
2. Pick units whose intent/triggers match the task    # e.g. "how do I get BPM for a track" → media-analysis
3. GET https://agent.kompo.se/docs/kcp/<unit>.md      # the territory: workflows, endpoints, formats
4. GET https://ai.makeshitapp.com/api/tools           # the typed operation manifest, straight from the API

You don't have to script that: kli init runs the whole chain and writes an AGENTS.md context file into your project — tools operations, knowledge units, auth status — and fails closed rather than leaving your agent with partial context. API responses themselves are agent-friendly too: send Accept: text/markdown and GET endpoints return formatted markdown instead of JSON (content negotiation).

Start your agent at getting-started, or point it at /llms.txt.

Proof it works

scenarios/first-video in the repository is a deterministic 8-stage rails runner plus an LLM playbook covering this exact flow — upload, analyze, compose, build, verify. It has produced a rendered video with duration, streams, and resolution independently checked by verify.ts.
